Covert Safety Application

Safe (SOS)

A covert emergency alert system for survivors of gender-based violence. It hides inside three everyday apps — a calculator, a weather app, and a clothing boutique — where hidden triggers quietly record audio or video, or send an SOS with live GPS location straight to emergency contacts.

Overview

Almost every safety product on the market shares one fatal assumption: that the victim can openly reach for her phone and use a visible emergency app. In a coercive, controlling environment that assumption collapses — a panic-button app is a neon sign an abuser finds in seconds, and visible help-seeking is punished. Safe is built around the real problem: victims need a way to alert trusted contacts and document abuse in real time, using a device the abuser can inspect at any moment, without any visible sign the phone is anything other than ordinary.

Safe is a single web app that presents three fully functional disguises. Each disguise is a real, working app; the safety triggers are woven into its normal interface. An olive green element captures video, a yellow one captures audio, and a pink one sends an SOS alert with live GPS location. Tap once to start, tap again to stop — the capture is saved to the device and emailed to contacts she chose herself. When a trigger is active the button turns red and nothing else changes: no labels, no popups, no sounds. Even the browser tab only ever shows the current disguise's name.

Key Features

Three Working Disguises

A working calculator, a real weather app, and a chic clothing boutique ("Maison"). There is no emergency mode screen, no special gesture, and nothing to hide when someone looks over her shoulder.

Colour-Coded Trigger System

Olive captures video, yellow captures audio, pink sends an SOS with live GPS. Triggers are styled as ordinary interface elements — calculator keys, weather UI, shopping buttons — with frozen labels so colour is the only signal.

Red-Only Activation State

When a trigger is active the button turns red — nothing else changes. No "Recording" or "Sent" text, no alerts, no sounds. The rule: if a piece of UI state would survive a screenshot in the wrong hands, it must be invisible.

Email Alerts with Attachments

The SOS email carries her name, her pre-written message, and a Google Maps pin of her live location. Audio/video alerts attach the recording as a playable MP4/M4A file, and the file is also saved on the device.

No-Server Privacy Architecture

No accounts, no server, no database. Profile and contacts live in the device's localStorage only — nothing to hack, nothing to subpoena, and nothing linking her to the service. Alerts fire silently while the disguise stays on screen.

Server-Side Key Handling

The Resend email API key never exists in the browser bundle. Locally a Vite dev-server proxy attaches it; in production a Vercel serverless function does — client code is identical in both environments.

Challenges & Decisions

The Email API Cannot Be Called from a Browser

Resend blocks browser calls with CORS, so the browser posts to same-origin /api/emails and a server-side proxy forwards to Resend while injecting the API key. One fix solved two problems: CORS disappeared, and the key stopped existing in client code entirely.

Attachments That Actually Open

Browsers record webm, which Gmail, iPhone Mail, and Outlook cannot play — and a base64 helper that sliced at the first comma corrupted every video because the MIME type contains a comma in its codec list. Recordings now negotiate MP4/M4A first, and the encoder works on raw bytes in 32KB chunks with no URL parsing.

It Must Always Send

A panic tool cannot lose the alert because a recording ran long. Three guarantees: record-time compression (24kbps mono audio, 320x240 video at 15fps), a size guard that drops an oversized attachment with a note in the email body, and a send path where one failing recipient never blocks the others.

Three Triggers, One Microphone

Audio, video, and SOS share device hardware and must never run in parallel. A promise-chain ownership lock serialises them: a new trigger stops the active one and awaits its full stop-save-send pipeline before starting.

Keeping the Disguise Airtight

Halfway through, the browser tab read "sos" — a total cover failure. Fixes: the static title became "Safe", a document.title effect maps every view to its disguise name, the favicon was audited, and trigger labels were frozen so colour is the only state signal.

SMS Died Behind a Paywall, Not Deleted

Twilio trial accounts refused the South African destination number, so the alert channel was rebuilt on Resend email by rewriting the three send modules as thin wrappers with identical signatures. The Twilio path remains in the codebase — restoring SMS is a rewire of three functions, not a rewrite.
