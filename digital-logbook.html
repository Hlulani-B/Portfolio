Microservices Architecture

Digital Logbook

A microservices-based digital logbook application with a React frontend and four independent Node.js/Express backend services, each running on its own port with Supabase for auth and PostgreSQL for data persistence.

Source Code Live Demo Documentation

Overview

Digital Logbook is a monorepo containing a React frontend and four independent backend microservices. Each service runs as its own process on its own port, following strict architecture rules: project entries and their statistics stay scoped to the project service, while the dashboard only shows cross-project summaries and never reads individual entry tables directly.

The Auth Service handles login and signup via Supabase Auth. The Dashboard Service provides cross-project summaries and search. The Project Service manages entries, timelines, search, statistics, and AI-powered features. The Profile Service handles user profiles, avatars, and preferences. All four services are deployed live on Render with auto-generated test coverage badges updated by CI on every push.

Key Features

Four Independent Microservices

Auth, Dashboard, Project, and Profile services each run on their own port (5001-5004) with independent deployments and scaling.

Supabase Authentication

JWT-based auth with Supabase, including JWKS URL verification, RPC functions for user management (delete, restore, purge).

AI-Powered Project Entries

The project service integrates multiple AI providers (OpenRouter, HuggingFace, Gemini, Cerebras, Groq) for natural-language features.

Cross-Project Dashboard

Aggregated summaries and search across all projects, following strict architecture boundaries that prevent direct entry table access.

CI/CD Pipeline

Gitea workflows run lint, build, and tests on every push and pull request. Coverage badges are auto-generated and committed to main.

Docker Compose Support

Full docker-compose.yml for local development of all services and the frontend together, with a render.yaml deployment manifest.

Architecture Decisions

Service Boundary Enforcement

Project entries and their statistics stay scoped to the project service. The dashboard service only shows cross-project summaries and never reads individual entry tables directly. This prevents tight coupling and keeps services independently deployable.

Protected Branch Strategy

Main and services branches are protected with no direct pushes allowed. All changes must go through pull requests with required approvals, ensuring code quality across the team.

Multi-Provider AI Integration

The project service supports five AI providers as fallbacks. If OpenRouter is down, the system tries HuggingFace, then Gemini, Cerebras, and Groq in sequence for natural-language features.
