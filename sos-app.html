SOS App

The cloud-backed evolution of Safe — a covert safety tool disguised as a weather app. One-tap hidden triggers record audio/video or alert trusted contacts with live location, while a map shows pals sharing their positions with real addresses and local weather.

Overview

A panic button only works if the person who needs it can reach it without the attacker noticing. Existing safety apps betray themselves: a red SOS icon, a "Send help" button, a screen that screams victim if a phone is grabbed and looked at. SOS App is the cloud-backed rewrite of the original offline Safe prototype — same disguise philosophy, but with cross-device trusted contacts and live location sharing powered by a real backend.

The chosen disguise is a weather app — universally boring and plausible to open at any hour. The weather screen lists ordinary cities, and three of them carry a small coloured dot: Johannesburg (olive) starts video, Durban (yellow) starts audio, Cape Town (pink) sends an alert with live location. A single tap loads that city's forecast and fires the hidden action; a red chip is the only visible state. A second Location screen shows trusted contacts ("pals") on a map, each resolved to a real street address with the current weather there.

Key Features

Weather-App Disguise Triggers

Three city chips hide the triggers. The dot colour is the only label, nothing is written on the buttons, and the screen looks identical to anyone else — tapping the same chip again stops the recording and sends what was captured.

Live Location Sharing

The share loop lives in a module-level singleton, not a component, so it keeps running when the Location page unmounts. The sharing state is mirrored to localStorage and resumed on boot, so a refresh never drops the share.

Pals & Invites System

Trusted contacts are chosen by her: send, accept, and remove invites, with pal profiles (names and avatars) merged with their live coordinates — pals without coordinates simply render as offline.

Map with Real Addresses & Weather

A react-leaflet map constrained to South Africa shows each online pal as an avatar marker. Address and weather are assembled from three free sources: Open-Meteo for weather, BigDataCloud for town/province, and a rate-limited Nominatim queue for the street.

Router-less by Design

No router on purpose: a localStorage view state machine means a refresh lands back on the same screen and the address bar never carries a hint of what the app is. Cover must survive scrutiny — tab title, branding, and every string stay innocuous.

Split Auth & Data Backends

Firebase handles only Google sign-in and the session (popup with redirect fallback); Neon Postgres is the sole store of app data. The email address is the bridge — after login the app checks whether the account is new.

Architecture & Challenges

Allowlisted Function Dispatcher API

Instead of one endpoint per operation, the Express API exposes modules at POST /api/module-name taking a function name and positional params. Every route holds an explicit allowlist of callable names, rejects cross-module names, and blocks prototype keys — with a trailing error handler keeping every response JSON.

The Share Loop Died on Navigation

With no router, switching screens unmounted the Location page and tore down the setInterval inside its useEffect — sharing silently stopped exactly when the user was least likely to notice. Moving the timer into a module-level singleton, then persisting it across refreshes, fixed it.

Free Geocoding APIs Each Have a Catch

BigDataCloud's free tier never returns street names; Nominatim does but throttles to 1 request/second and blocks generic user-agents. The address is a three-source chain with a serialised Nominatim queue (~1100ms spacing) and graceful degradation when a field is missing.

Windows Hides Bugs That Break Linux

A folder committed as api/Routes/ but imported as ./routes/ ran fine on Windows and crash-looped on Render's Linux with ERR_MODULE_NOT_FOUND. Fixed with a two-step git mv case rename — a local "it works" is not proof of case-correctness.

The Render Blueprint Is Stricter Than It Looks

A static site is type: web with runtime: static and a staticPublishPath — type: static is not valid at all. And sync: false env vars don't fail; the blueprint just sits "Running" while it waits for secrets to be typed into the dashboard.

Postgres Types Are Not What They Look Like

NUMERIC coordinates come back from the driver as strings ("-33.920000"), needing an explicit Number() before plotting. And because the dispatcher passes params positionally, array arguments must be nested or Postgres throws a malformed array literal.
